# 승인 체크리스트 v1

v1 · 2회차 — 오늘 바뀐 점
- 테스트 통과: "테스트가 충분하다"를 "새 public 메서드(접근자 제외)마다 테스트가 1개 이상 있다"로 바꿨다.
- 치명 이슈: 행안부 구현단계 보안약점 검토 통과 · 비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립 다섯 가지로 정했다.
- 범위 · 컨벤션: 범위 밖 변경은 같은 파일 안 import 정리만 허용한다. 계층 위반 · 빈 catch · System.out 은 반려, 네이밍은 경고다.

AI 가 만든 변경분 · 외주사 PR 을 머지하기 전에 리뷰어가 대조하는 목록이다. 모든 항목은 **예 / 아니오**(판단 근거가 없으면 "확인 필요")로 답한다.
**[반려]** 항목이 하나라도 "아니오"면 반려다. **[경고]** 항목이 "아니오"면 이슈 목록에 경고로 남기고 판정에는 반영하지 않는다.

## 심각도 정의

- **치명** — 2절의 다섯 유형(행안부 보안약점 · 비밀값 노출 · 데이터 손실 · 인증 우회 · SQL 문자열 조립) 중 하나에 해당한다. 1건이라도 있으면 반려.
- **경고** — [경고] 항목 위반, 또는 다섯 유형에 들지 않지만 다음 변경에서 사고가 날 수 있는 문제(예: N+1 쿼리). 판정에 영향을 주지 않고 수정 요청 목록에 남긴다.
- **제안** — 더 나은 방법이 있다는 의견. 판정에 영향을 주지 않는다. 목록으로만 남긴다.

이슈 한 건은 심각도 · `파일:줄번호` · 근거 · 수정 방향 네 항목으로 적는다. 근거 줄번호를 댈 수 없는 지적은 "확인 필요"로 따로 둔다.

## 판정 형식

첫 줄에 `판정: 승인` 또는 `판정: 반려`. 이어서 네 기준의 충족 · 미충족 표(미충족이면 "아니오"가 나온 항목 문장을 인용), 행안부 구현단계 보안약점 검토 표, 이슈 목록(심각도 · `파일:줄번호` · 근거 · 수정 방향) 순서로 적는다. 행안부 표 아래에 "이 검토는 사람이 읽는 수동 검토이며 Sparrow 정적 분석 결과를 대신하지 않는다"를 적는다. 코드는 수정하지 않는다.
