# RCA 리포트 마스킹 규칙

리포트(`docs/rca/<시나리오>.md`)를 저장하기 전에 리포트 전체에 적용한다. 원본 로그는 절대 고치지 않는다.
치환은 메모리 안에서만 한다. 원본 ↔ 별칭 대응표를 파일로 남기지 않고, 마스킹 전 원본을 임시 폴더에 복사하지 않는다.

## 치환 규칙

| 유형 | 치환 | 예 |
|---|---|---|
| IP 주소 | 앞 두 옥텟만 남기고 나머지는 `x` | `10.20.x.x` |
| 구분이 필요한 IP | 역할 별칭. 응답한 서버와 연결을 거부한 서버, 반복 요청한 단말처럼 분석에 쓰이는 값 | `API-1` · `API-2` · `교사단말A` |
| 이메일 | 아이디를 `***` 로, 도메인은 유지 | `***@example.com` |
| 학생 식별자 (`STU-<숫자>`) | 리포트 안 등장 순서대로 `학생A`, `학생B` … 같은 학생은 끝까지 같은 별칭 | `student=학생B` |
| 토큰 · 세션 ID · API 키 · `Authorization` 헤더 값 | `[TOKEN]` | `Authorization: [TOKEN]` |
| 비밀번호 · 접속 문자열 | `[SECRET]` | `password=[SECRET]` |

- 역할 별칭은 리포트 안에서 한 번 정의하고(예: "읽는 법" 항목) 끝까지 같은 값을 쓴다. 본문의 축약형(`` `.22` `` 처럼 마지막 옥텟만 쓴 값)도 같은 별칭으로 바꾼다.
- 학생 식별자를 `STU-*` 처럼 뭉개 두었던 발췌가 있으면, 인용한 원본 줄(`파일:줄번호`)에서 실제 값을 확인한 뒤 별칭을 붙인다. 그래야 "같은 학생의 반복 요청"이라는 단서가 남는다.
- 부록의 명령 · 출력 안의 값도 치환한다. 이 경우 명령을 그대로 다시 실행할 수 없으므로 리포트에 그 사실을 적는다.

## 확인 절차

1. **패턴이 원본에서 걸리는지 먼저 본다.** 원본에 돌린 결과가 0이 아닌 파일이 하나 이상 있어야 다음 단계의 "출력 없음"을 믿을 수 있다. 전부 0이면 로그의 표기에 맞게 패턴을 고친다.

   ```bash
   P='([0-9]{1,3}\.){3}[0-9]{1,3}|[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[a-z]{2,}|STU-[0-9]+|Bearer [A-Za-z0-9._-]{8,}'
   grep -cE "$P" incident-logs/<시나리오>/*
   ```

2. 원본에서 유형별로 무엇이 있는지 센다(IP · 이메일 · `STU-` · `Bearer` · `token=` · `password=` 등). 패턴에 없는 표기(예: `session=`, `api_key=`)가 보이면 따로 grep 한다.
3. 리포트에 같은 패턴을 돌린다. **아무것도 출력되지 않아야** 한다: `grep -nE "$P" docs/rca/<시나리오>.md`
4. 패턴에 안 걸리는 축약형 IP(`` `.21` ``), 이전에 임시로 가린 표기(`STU-*` · `<가림>`)가 남았는지도 grep 으로 확인한다.
5. 리포트 맨 아래에 한 줄을 남긴다.
   `마스킹 적용: IP N건(역할 별칭 …) · 학생 식별자 N건(별칭 M명) · 토큰 N건 · 이메일 N건 · 비밀번호 · 접속 문자열 N건`
