# 변경 영향 조사

대상: `$ARGUMENTS`. 비어 있으면 무엇을 조사할지 묻고 멈춘다. 읽기만 한다. 결과는 답변으로만 내고 파일을 만들지 않는다.

## 1. 대상 확정

- `파일:줄번호` 면 그 줄을 감싼 함수가 대상이다. 이름이면 정의를 찾는다.
- 정의가 둘 이상이면(오버로드, 레거시와 modern 에 같은 이름) 후보를 `파일:줄번호` 로 나열하고 고르게 한다.
- 검색에서 뺄 곳: `node_modules/`, `build/`, `legacy/*/vendor/`.

## 2. 진입점까지 거슬러 오르기

호출문을 찾아 한 단계씩 올라간다. 진입점에 닿거나 이미 본 함수를 다시 만나면 멈춘다.

| 위치 | 진입점 |
|---|---|
| `legacy/item-bank-php` | 브라우저가 여는 최상위 `.php` (`require` 되는 파일은 거쳐 간다) |
| `legacy/assignment-thymeleaf` · `legacy/grade-mssql` | `@*Mapping` 메서드의 URL + 돌려주는 템플릿 |
| 저장 프로시저 | `EXEC` 하는 코드 → 그 코드의 진입점 |
| `modern/api` | `@RestController` 메서드의 URL. 이어서 `modern/web/src/api` → `hooks` → `components` 에서 그 URL 을 부르는 화면 |

경로는 `진입점 → … → 대상` 한 줄에 단계마다 호출문 `파일:줄번호` 를 단다.

## 3. 테이블

- 대상과 대상이 부르는 함수의 SQL · JPQL · 리포지토리 메서드에서 읽기 / 쓰기 테이블을 찾는다.
- 테이블마다 같은 테이블을 쓰는 다른 함수를 `legacy/` · `modern/` · `db/` 에서 찾는다. 스키마는 `db/mariadb/init/01-schema.sql` · `db/mssql/init/01-schema.sql`, 정리된 표가 있으면 `docs/<모듈>/ERD.md` 와 대조한다.

## 4. 이관 짝 — 이 저장소에만 있는 단계

- 대상이 `legacy/` 에 있으면 modern 쪽 짝을, `modern/` 에 있으면 레거시 원본을 찾는다. 단서는 Javadoc 의 레거시 `파일:줄번호` 인용, `characterization/lib/target.mjs` 의 `PATH_ALIASES`, `docs/<모듈>/BUSINESS-RULES.md` 의 규칙 ID 다.
- 한쪽만 고치면 동작 보존 테스트가 갈라질 수 있다. 짝이 있으면 "같이 봐야 할 곳"으로 적는다.
- `docs/verify/` 의 이관 검증 리포트에 대상이 나오면 그 이슈 번호와 미해소 여부를 적는다.

## 5. 테스트

- 이미 있는 것: `modern/*/src/test`, `characterization/tests` 에서 대상 · 진입점 URL 을 다루는 테스트를 `파일:줄번호` 로 적는다. `characterization` 은 응답 모양만 비교하므로 내부 분기를 다 덮지 못한다는 점을 함께 적는다.
- 비어 있는 것: 위 경로 · 테이블 · 규칙 중 어떤 테스트도 지나지 않는 분기를 "입력 → 기대 결과"로 제안한다. 경계값과 빈 값을 넣는다.

## 출력 (순서 고정)

1. 대상 — 이름, 정의 `파일:줄번호`, 한 줄 설명
2. 영향받는 진입점 — URL · 화면 · 배치, 근거
3. 호출 경로
4. 테이블 — 대상의 읽기/쓰기, 같은 테이블을 쓰는 다른 함수
5. 이관 짝과 관련 규칙 ID — 없으면 "없음"
6. 테스트 — 있는 것 / 비어 있는 것
7. 확인하지 못한 경로 — 리플렉션, 문자열로 만든 SQL · URL, 동적 `include`, 외부 시스템 호출처럼 검색으로 확정할 수 없는 곳과 무엇을 보면 확정되는지

근거 `파일:줄번호` 를 댈 수 없는 내용은 1~6 에 넣지 않고 7 로 옮긴다.
