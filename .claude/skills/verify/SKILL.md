# 변경분 검증

검증 대상: $ARGUMENTS

- `$ARGUMENTS` 가 비어 있으면 `git diff upstream/main...HEAD` 를 검증 대상으로 삼는다.
- 이 절차는 저장소 루트의 `templates/verification-loop.md` 를 옮긴 것이다. 판정 항목은 저장소 루트의 `templates/approval-checklist.md` 를 그때그때 읽어서 쓴다. 이 파일에 항목을 옮겨 적지 않는다.

## 하지 말 것

- 코드를 수정하지 않는다. 판정과 수정 방향만 보고한다. 고치기 시작하면 리뷰가 아니라 만든 쪽이 된다.
- 근거 줄번호를 댈 수 없는 지적은 이슈로 올리지 않고 "확인 필요"로 따로 남긴다.
- 테스트를 실행하지 않고 "통과"라고 쓰지 않는다. 실행할 수 없었으면(서버 꺼짐, 의존성 미설치) 그 사실을 적고 사람에게 기동을 요청한다.
- 전체 로그를 대화에 싣지 않는다. 테스트 결과는 통과 · 실패 수와 실패한 테스트 이름만 남긴다.

## 절차

### 1. 요청 범위 확인

- 무엇을 요청했는지 한 문장으로 확인한다. `$ARGUMENTS` 나 대화에 요청 문장이 없으면 **판정하지 말고 먼저 질문한다.**
- 요청 범위를 모르는 상태에서 "요청 범위 이탈 없음"을 충족으로 표시하지 않는다.

### 2. 변경 파일 목록과 diff 읽기

- git 범위면 `git diff --stat <범위>` 로 목록을 먼저 보고, 파일마다 `git diff <범위> -- <파일>` 로 읽는다.
- patch 파일이면 `git apply --stat <파일>` 로 목록을 뽑고 patch 본문을 읽는다.
- 변경 파일을 `modern/api` · `modern/web` · `characterization` · 그 밖으로 나눠 둔다. 4단계에서 실행할 테스트를 이 분류로 정한다.

### 3. 체크리스트 대조

- 저장소 루트의 `templates/approval-checklist.md` 를 읽는다. 심각도 정의(치명 / 경고 / 제안)도 이 파일을 따른다.
- 항목마다 충족 · 미충족 · 확인 필요 중 하나로 표시한다.
- 컨벤션 항목은 저장소 루트의 `CLAUDE.md` 와 대조한다. `convention-check` Skill 이 있으면 그 결과를 근거로 쓴다.

### 4. 테스트 실행

변경된 폴더의 테스트만 실행한다.

| 변경 폴더 | 명령 |
|---|---|
| `modern/api` | `cd modern/api && ./gradlew test` |
| `modern/web` | `cd modern/web && npm test` |
| 이관 코드(레거시 → `modern/`) | `cd characterization && npm test` (레거시 대상) 와 `cd characterization && TARGET_BASE_URL=http://localhost:8080 npm test` (새 API 대상) |

- 새 API 대상 테스트는 `modern/api` 서버가 8080 에 떠 있어야 한다. 떠 있지 않으면 실행하지 않고 그 사실을 적는다.
- 출력은 통과 · 실패 수와 실패한 테스트 이름만 남긴다. 필요하면 `tail` · `grep` 으로 요약 줄만 뽑는다.

### 5. 승인 기준 판정

- 네 기준(테스트 통과 / 치명 이슈 0건 / 요청 범위 이탈 없음 / 컨벤션 준수)을 하나씩 판정한다. 하나라도 미충족이면 반려.
- 이슈가 0건이면 경고 · 제안 수준까지 한 번 더 본다. 0건은 결과일 수도, 안 본 것일 수도 있다.

## 출력 형식

```
판정: 승인 | 반려

| 기준 | 결과 | 근거 |
|---|---|---|
| 테스트 통과 | 충족 / 미충족 | 실행 명령과 통과 · 실패 수, 실패한 테스트 이름 |
| 치명 이슈 0건 | 충족 / 미충족 | 치명 이슈 번호 |
| 요청 범위 이탈 없음 | 충족 / 미충족 | 요청 문장 vs 변경 파일 목록 |
| 컨벤션 준수 | 충족 / 미충족 | 위반 이슈 번호 |

이슈 목록
| # | 심각도 | 파일:줄번호 | 근거 | 수정 방향 |
|---|---|---|---|---|

확인 필요
- (근거 줄번호를 댈 수 없는 지적)
```

- 이슈 한 건은 심각도(치명 / 경고 / 제안) · `파일:줄번호` · 근거 · 수정 방향 네 항목을 모두 채운다.
