# 4MAT 학습 가이드

학습 주제: $ARGUMENTS

- 주제가 비어 있으면 가이드를 쓰지 말고 무엇을 설명할지 먼저 묻는다.
- 추상적인 지식을 나열하지 않는다. 학습자가 바로 이해하고 실무에 응용할 수 있도록 **Why → What → How → What if** 순서를 반드시 지킨다.
- 서론 · 인사말 없이 1번 섹션부터 바로 시작한다.
- 이 스킬은 설명만 한다. 코드 · 설정 파일을 수정하지 않는다.

## 원칙

1. **Why 로 시작한다.** 배경과 필요성을 모르면 지식을 온전히 흡수하지 못한다. 도입부에서 "왜 등장했고 왜 필요한지"부터 납득시킨다.
2. **구체적인 예시를 먼저 든다.** 정의만 늘어놓지 않고, 현실 · 실무와 가까운 비유와 예시를 바로 붙인다.
3. **정교화 질문을 넣는다.** 섹션 중간에 "왜 이런 구조로 설계했을까?", "기존 방식에는 어떤 문제가 있었을까?" 같은 질문을 던지고 바로 답한다. 각 섹션에 최소 1개.
4. **바로 적용해 볼 시나리오로 끝낸다.** 학습자가 자기 작업 환경이나 프로젝트에 대입해 볼 수 있는 What if 로 마무리한다.

## 이 저장소의 주제일 때

- 주제가 이 저장소의 코드 · 문서 · 실습(예: 동작 보존 테스트, `/verify`, OSIV, 커넥션 풀)과 관련 있으면, 예시를 지어내지 말고 실제 파일을 Read · Grep 으로 찾아 `파일:줄번호` 로 인용한다.
- 저장소와 관련 없는 일반 주제는 파일을 뒤지지 않고 바로 설명한다.

## 출력 구조 (순서 고정)

### 1. Why? — 왜 알아야 하는가
- **기존 문제점:** 이전 방식의 한계나 비효율
- **존재 이유:** 이 기술 · 개념 · 도구가 왜 만들어졌고, 지금 왜 배워야 하는가
- **핵심 효용:** 도입했을 때 얻는 분명한 이점

### 2. What? — 본질과 핵심 원리
- **정의:** 본질을 짚는 한두 문장 요약
- **비유 · 멘탈 모델:** 일상이나 익숙한 엔지니어링에 빗댄 설명
- **핵심 구성 요소:** 구조도(텍스트 다이어그램) · 핵심 키워드 · 동작 흐름 요약

### 3. How? — 어떻게 쓰는가
- **적용 흐름:** 단계별 구현 순서와 핵심 절차
- **예시 · 코드:** 주석을 단 짧은 예시. 흔한 실수를 막는 팁과 권장 방식을 함께 적는다.
- **작동 원리:** 코드가 실제로 돌 때 안에서 무슨 일이 일어나는가

### 4. What if? — 내 상황에 적용한다면
- **실무 시나리오:** "실제 프로젝트 · 트래픽 · 확장성 요구사항에 도입한다면?"
- **예외 상황과 주의점:** 어떤 조건에서 한계가 생기고 어떻게 대처하는가
- **점검 질문:** 이해도를 확인할 핵심 질문 1~2개(답은 적지 않는다)

## 문체

- 군더더기 없이 명확하고 논리적이며 실용적으로 쓴다.
- 한국어로 쓰고, 코드 식별자 · 명령 · 로그 원문은 그대로 둔다.
