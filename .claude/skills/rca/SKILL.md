# 장애 로그 RCA

대상: `incident-logs/$ARGUMENTS/` · 결과: `docs/rca/$ARGUMENTS.md`
인자가 비어 있거나 폴더가 없으면 시작하지 말고 `ls incident-logs/` 결과를 보여 주며 묻는다.
리포트는 절마다 저장하고, 각 절 첫머리에 그 절이 하는 일과 하지 않는 일(예: "원인 추정은 하지 않는다")을 적는다.
**리포트를 저장하기 전에 `.claude/skills/rca/masking-rules.md` 의 규칙을 적용한다.** 처음 저장할 때부터 적용한다.

## 절차

1. **수집 범위** — 파일을 통째로 읽지 않는다. `wc -l` · `head` · `tail` · `grep -c` · `awk` 로 파일별 줄 수 · 기록 기간 · 시각 형식 · 타임존을 표로 만든다.
   - 오프셋이 없는 파일은 다른 파일의 같은 사건과 시각을 맞춰 타임존을 판정하고 근거를 적는다(예: epoch 값 ↔ 표기 시각).
   - 분 단위로 WARN · ERROR · 5xx 를 세어 평소 수준과 이상 구간을 정하고, 앞뒤 여유를 붙여 수집 범위를 확정한다.
2. **타임라인** — 수집 범위 안의 사건을 KST 한 시간축으로 합친다. 모든 줄에 `파일:줄번호` 를 단다.
   - 원인 해석은 쓰지 않는다. 반복 메시지는 첫 줄에 "이후 N건"으로 묶는다.
   - 정밀도가 다른 파일끼리 2초 안에 찍힌 사건은 "(선후 불확실)"로 표시한다.
   - 가장 많이 나온 오류의 첫 시각을 찾고, 그보다 앞선 평소와 다른 사건을 **[선행]** 으로 표시한다.
   - 찾았지만 없었던 사건(재시작 · 설정 재적재 · 트래픽 급증 등)도 검색어와 함께 적는다.
3. **가설** — 서로 다른 계층(코드 / DB · 쿼리 / 트래픽 / 인프라 / 배포 · 설정)에서 2개 이상 세운다.
   - 가설마다 표: 가설 한 문장 · 지지 근거(`파일:줄번호`) · 반증 조건 · 확인 방법(실행할 명령 또는 열어 볼 파일).
   - 반증 조건은 "무엇이 확인되면 틀린가"를 명령 결과로 판정할 수 있는 문장으로 쓴다.
   - 가장 많이 나온 오류는 증상 표로 따로 분리한다. 이 단계에서는 판정하지 않는다.
4. **검증** — 로그로 확인할 수 있는 확인 방법을 실제로 실행한다.
   - 명령 원문과 결과 숫자를 부록(C1, C2 …)에 그대로 남긴다.
   - 집계 결과가 이미 아는 총계(예: ERROR 건수)와 맞는지 먼저 대조한다. 틀린 집계는 버린 이유와 함께 남기고 다시 센다.
   - 가설마다 `유지` / `기각` / `판단 불가(로그 부족)` 를 판정하고 이유를 한 줄로 적는다. 판단 불가면 어떤 로그가 있었어야 하는지 적는다.
   - 유지된 가설은 로그에 찍힌 클래스 · 메서드 · 설정 키로 코드를 찾아 대조한다. 판정은 지지 / 반박 / 관련 코드를 찾지 못함 중 하나다.
   - 설정값은 파일에서 읽은 값만 쓴다. 측정하지 않은 성능 추정은 "추정"이라고 표시한다.
   - 채택 가설 하나와, 채택하지 않은 가설별 사유, 확신 수준(높음 / 중간 / 낮음)과 그 이유를 적는다.
5. **리포트** — 맨 위에 5줄 이내 요약(무슨 일 · 언제부터 언제까지 · 원인 · 확신 수준)을 두고, 이어서 아래 절을 쓴다.
   - 원인: 인과 순서로 쓰고 직접 원인과 배경 원인을 구분한다.
   - 근거 로그 줄: 원인 문장마다 `파일:줄번호` 와 발췌를 단다.
   - 수정안 / 재발 방지 / 모니터링 항목은 서로 섞지 않는다. 수정안은 제안만 하고 코드는 바꾸지 않는다.
   - 모니터링 항목: 지표 · 임계값마다 이번 타임라인에서 경보가 울렸을 시각과, 사용자 영향 시작 몇 분 전이었는지를 적는다.
   - 확인하지 못한 것: 판단하지 못한 부분과 다음을 위해 남겨야 할 로그를 짝지어 적는다.
6. **마스킹 · 저장** — `masking-rules.md` 를 적용하고 확인 절차를 돌린다. 리포트 맨 아래에 "마스킹 적용: 유형별 건수" 한 줄을 남긴다.

## 하지 말 것

- 로그에 없는 줄을 인용하지 않는다. 근거가 없으면 "로그로 확인 불가"라고 쓴다.
- 가장 많이 나온 오류를 곧바로 원인이라고 부르지 않는다. 그것은 증상이다.
- 원본 로그와 소스 코드를 수정하지 않는다.
- 마스킹 대응표를 파일로 남기지 않는다.
- 마스킹 전 원본을 임시 폴더에 복사해 두지 않는다.
- 사용자가 범위를 줄였으면(예: "1~3절까지만") 그 지점에서 멈추고 남은 절을 쓰지 않는다.
